# 物件選別ツール（チーム作業用・提出物ではない）

MVP で SOZORO がサジェストする**文化財と飲食店を、5人で手分けして 50〜100件ずつに絞る**ための画面。

採用状態は D1 に入るので、全員の画面に数秒で反映される。誰が採ったかも残る。
選び終わったら CSV / JSON / SQLite で落として開発メンバーに配る。

## なぜ本番と別の Worker なのか

提出するデモ URL（`sozoro.opd-hackathon-b.workers.dev`）に内輪の作業画面をぶら下げると
審査員から見えてしまう。選別が終わったらこの Worker だけ消せばよい。
D1 は同じ `sozoro` を共有するので、採用結果はそのまま本番のシードに使える。

## 3つのふるい

候補は5,093件（文化財422 / 飲食店4,671）。ここから3段で落とす。

**1. 業種（`curate_prefilter.py`・機械的）**
バー・キャバレー599 / スナック320 / コンビニ175 / そうざい製造195 / 弁当168 /
旅館ホテル195 / 集団給食100 など、散歩の着地点にならないものを落とす。
理由は辞書にコメントで残してあるので戻せる。

**2. 混雑エリア（画面のフィルタ・既定オン）**
SOZORO は上野・浅草の混雑を**散らす**アプリなので、混雑コアそのものに人を送るのは目的と逆。
`congestion.json` のランドマークのうち、来訪者アンケートで「残念だったこと＝人の多さ」の
回答率が最上位だったエリア（上野1.0・浅草0.952）の5地点を混雑コアとする。

> 雷門・浅草寺・仲見世通り・上野公園・アメヤ横丁

既定は**半径500m以内を除外**。この設定で落ちるのは 文化財30件 / 飲食店2,647件。
浅草寺・雷門・浅草神社・伝法院・上野の大仏・上野東照宮・国立西洋美術館・
国立科学博物館・上野動物園・清水観音堂などが外れる。**狙いどおり有名どころが消える。**

半径はスライダで変えられる。何が消えるか見てからチームで決めればよい。

| 半径 | 除外される文化財 | 残り | 除外される飲食店 | 残り |
|---:|---:|---:|---:|---:|
| 300m | 15 | 407 | 1,626 | 3,045 |
| 400m | 24 | 398 | 2,255 | 2,416 |
| **500m** | **30** | **392** | **2,647** | **2,024** |
| 600m | 41 | 381 | 2,919 | 1,752 |
| 800m | 74 | 348 | 3,316 | 1,355 |

**3. 星と口コミ（画面のフィルタ・既定 星3.5以上・口コミ20件以上）**
これは**上位を選ぶためではなく、下限を切るため**に使う。
星の高い順に上から採ると「すでに混んでいる有名店」ばかりになり、分散という目的と逆を向く。
下限を割ったものを落としたら、あとの50〜100件は人が選ぶ。

## 立ち上げ（管理する人が1回だけ）

```sh
cd SOZORO/tools/curate

# 作業台のテーブルを作る
wrangler d1 execute sozoro --remote --file=schema.sql

# チームで共有する合言葉を入れる（推測されにくいものにすること）
wrangler secret put CURATE_PASSWORD

# 地図の鍵。これを入れておけばメンバーは何も設定しないで地図が見られる
wrangler secret put GOOGLE_MAPS_KEY

wrangler deploy
# → https://sozoro-curate.<サブドメイン>.workers.dev
```

### 地図の鍵の扱い

**鍵はリポジトリに書かない。** Worker のシークレットに入れ、合言葉を通った人にだけ
`/api/config` から配る。ソースにも git にも残らない。

ただし Maps JavaScript API の鍵は**仕組み上どうせブラウザに出る**（script の URL に載るので、
開発者ツールを開けば読める）。これは Google の設計上そうなっていて、隠す方法は無い。
**本当の防御は Google Cloud 側のリファラ制限**なので、必ずかけること。

> Google Cloud コンソール → APIとサービス → 認証情報 → 鍵を選ぶ
> → アプリケーションの制限 → **HTTPリファラー** → 次の2つを許可
>   `https://sozoro-curate.<サブドメイン>.workers.dev/*`
>   `http://localhost:8787/*`（手元で試す用）
> → APIの制限 → **Maps JavaScript API** だけに絞る

こうしておけば、鍵が漏れても他所のサイトからは使えない。
また **Maps JavaScript API だけに絞る**ことで、万一の場合も Places のような
高い SKU が叩かれない。地図の読み込みは Essentials（月10,000回無料）。

候補データ（`public/data/curation.json`）は生成物なので git には入っていない。
デプロイ前にひとつ上のフォルダで作る。

```sh
cd ../../..                                   # 東京都ハッカソン2026/
python3 scripts/curate_prefilter.py           # → data/curation/candidates.csv
export GOOGLE_PLACES_KEY=...
python3 scripts/curate_fetch_google.py --dry-run   # まず下見（無料枠を食わない）
python3 scripts/curate_fetch_google.py             # 本番（上限900呼び出しで停止）
python3 scripts/curate_match.py               # → public/data/curation.json
```

## 選ぶ人（5人）

URL と合言葉を受け取って開く。入れるのは**名前と合言葉だけ**（名前は誰が採ったかを残すため）。
**地図の鍵の設定は要らない。** サーバから配られる。

- **ピンは2色だけ … 赤=採用済み / 灰=まだ判断していない。**
  誰が採ったかは地図では区別しない（進み具合を一目で見るための画面なので、
  色を増やすと読めなくなる）。星の高低は一覧の ★ を見る
- 一覧のほうは 緑の行=自分が採った / 薄紫の行=他の人が採った、で区別できる
- ピンの大きさ … 採用済み＞文化財＞飲食店
- ヘッダの件数は4秒ごとに更新される。誰が何件採ったかも出る
- 一度採ったものはフィルタを変えても消えない（他の人の作業を勝手に隠さないため）
- `座標が丁目代表点` の印 … 文化財CSVの座標は丁目単位。Google に照合できれば正確な座標に
  差し替わるが、できなければ**採用しても本番では `hidden` のまま**になる
  （「あと〇〇m」が嘘になるため。`build_seed_sql.py` が弾いて件数を報告する）

**分担のしかた**: 「並び順→町字ごと」にして町字で分ける、
または「上野から遠い順」で距離帯を分けると、5人の担当が重ならない。

## 落とす（開発メンバー）

画面右上の **CSV / JSON / SQL** から直接落とせる。SQLite が要るなら手元で作る。

```sh
export CURATE_URL=https://sozoro-curate.<サブドメイン>.workers.dev
export CURATE_PASSWORD=...
python3 scripts/curate_pull.py
```

出るもの:

| ファイル | 中身 |
|---|---|
| `data/share/curated.csv` | 表計算で開ける |
| `data/share/curated.json` | そのまま読める |
| `data/share/curated.sqlite` | `curated` テーブル。`sqlite3` で引ける |
| `data/curation/curated.json` | `build_seed_sql.py` が読む採用リスト |

最後のものを置いて `python3 scripts/build_seed_sql.py` を回すと、
本番のシードが**採用した文化財・飲食店だけ**になる。
このファイルを消せば元の全件表示に戻る。他のレイヤー（体験する・静かに歩く）には触らない。

## 課金について

Google Maps Platform の無料枠は 2025年3月から **SKU ごとの月間上限**になっている。
プールは共有されない。

| SKU | 該当するもの | 月の無料枠 |
|---|---|---:|
| Essentials | place ID だけ・地図の読み込み | 10,000 |
| Pro | 名前・住所・写真の参照名 | 5,000 |
| **Enterprise** | **rating / userRatingCount / Place Photo の実体** | **1,000** |

星を取る呼び出しは必ず Enterprise に落ちる。候補は5,093件なので
**1件1呼び出しの照合では無料枠に収まらない**。そこで `curate_fetch_google.py` は
個別照合をせず、上野周辺を矩形タイルで**面で検索**する。1呼び出しで最大20件返るため、
900呼び出しで最大18,000件ぶんの評価が取れる。タイルが満杯（20件）なら4分割して掘る。

守りの仕掛け:

- **キャッシュ** … 1リクエスト1ファイル。同じ呼び出しは二度としない
- **使用量の記録** … `data/curation/api_usage.json` に月ごとの呼び出し数
- **ハード上限** … 既定900で打ち切る。途中で止まってもそこまでは保存され、翌月続けられる
- **下見モード** … `--dry-run` は `places.id` だけ要求するので Essentials（月10,000）で動く。
  **本番はやり直しがきかないので必ず先に下見する**

**写真は出さない方針にしたので、Place Photo は一切呼んでいない。** 判断材料は
星・口コミ数・位置関係で足りるうえ、写真は Enterprise（月1,000枚）を食う。
必要になったら `curate_match.py` が `google.photos` に参照名を残してあるので後から足せる。

地図そのものは Maps JavaScript API（**Essentials・月10,000回無料**）。
5人で数日触る程度では無料枠に届かない。

## 承知のうえの割り切り

- 合言葉と地図の鍵はヘッダ・URLに平文で載る。内輪の作業台なのでこれで十分だが、
  **公開URLに置く以上、強い合言葉にすること**。済んだら Worker を消す
- 更新は4秒ごとのポーリング。WebSocket や Durable Objects でもできるが、
  捨てる道具なので一番壊れにくいやり方にした
- 同じ物件を2人が同時に押したら、あとに押したほうの名前が残る（上書き）
- 元データの一部に文字化け（`秀寿?` など）がある。台東区CSVの環境依存文字が
  由来で、選別時に気づいたら外すか、`data/destinations.csv` 側を直す
